Flujo de autenticación

  • El frontend redirige al Hosted UI de Cognito (code + PKCE).
  • Cognito devuelve un JWT con el claim cognito:groups.
  • El API Gateway valida el token antes de enrutar.
  • Spring Security valida firma, issuer, expiración y audience.

Flujo de mensajería

  • Direct exchange → notificaciones.
  • Topic exchange → tickets y documentos.
  • Error de negocio → NACK → DLX → DLQ.
  • Topología declarada por código y por definitions.json.

Infraestructura

Tarea 4 · Cognito y API Gateway

Seguridad

IDaaS · AWS Cognito

  • User Pool pedidos360-pool con login por email.
  • Grupos: ADMIN COLLABORATOR CUSTOMER
  • App Client SPA sin secret · Authorization Code + PKCE.
  • Hosted UI con dominio propio de Cognito.

API Gateway + autorización

  • HTTP API con integración proxy a la EC2.
  • Autorizador JWT (issuer + audience del User Pool).
  • Ruta pública: GET /api/health.
  • Rutas protegidas: ANY /{proxy+}.

Reglas del backend por rol:

GET autenticado · POST/PUT ADMIN/COLLAB · DELETE ADMIN
